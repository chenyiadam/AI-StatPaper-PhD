# stat-simulation-audit · Experiments & code audit

## Hard disciplines

1. **Deterministic code does the grunt work; LLM only judges** (Polaris
   principle): scripts run experiments; AI never "computes" numbers itself; AI
   interpretations may only cite numbers that exist in the output tables.
2. **Audit before running**: reviewing code is far cheaper than reviewing
   papers; the production run requires passing this skill's audit.
3. **Record failures**: non-convergence becomes a failure rate in the table;
   silently dropping scenarios is forbidden.
4. **The seed is the identity**: every number is reproducible from
   (scenario × replication × seed rule).

## Workflow

### A. Design (before coding)
1. Run **P13** (`prompts/en/04`): the five deliverables — scenario grid (each
   value tagged to the theorem assumption it satisfies/stresses/violates) → DGP
   pseudocode (formula-by-formula with the paper) → metrics table (formula +
   which theorem conclusion) → baseline-fairness protocol (baselines get tuned
   too) → failure protocol.
2. Start from the skeleton `templates/simulation/sim_design.R` or `.py`
   (seed rule, one-pass metrics, tidy output built in).
3. Check against `checklists/en/C3-experiments.md` groups A–B.

### B. Code audit (before the run)
Run **P14**: DGP-vs-doc consistency (#1 bug source) → seed discipline and
hidden RNG → statistical correctness (coverage vs. the true parameter, TPR/FDR
denominators, size formula, CV leakage) → boundaries & failure capture →
reproducibility → performance traps. Then the **10-minute smoke test**
(n=50, p=10, rep=20): validate output shapes and magnitudes.

### C. Interpretation (after the run)
1. Run **P15**: faithful table-to-prose — table numbers only, every pattern
   with exact numbers, theory check-in, and DISAGREEMENTS reported honestly
   with candidate explanations.
2. AI must output the "number–cell reconciliation table"; the author checks it
   row by row (number-provenance discipline).
3. Presentation: three-digits rule, bolded best values with a stated criterion,
   self-contained captions (via **P19** in `prompts/en/05`).

### D. Real data
1. Run **P16**: fit assessment → preprocessing protocol (two missing-value
   treatments; outlier rules fixed before looking) → main + sensitivity
   analyses → interpretation-bounds statement ("consistent with" < "suggests" <
   "shows" < "proves").
2. Check `checklists/en/C3-experiments.md` group D; the data-availability
   statement is mandatory.

### E. Replication package (before submission)
1. TIER-4.0-style layout: `data/ code/ output/ docs/` + README with the
   one-command run.
2. Locked environment: `requirements.txt` / `renv.lock` / `environment.yml`
   with interpreter versions.
3. All figures/tables regenerated by scripts and matching the paper; code
   archived on Zenodo/OSF with a DOI.
4. Sensitive-info scan: API keys, local paths, personal data = zero.

## Cross-checks

- Theory consistency: λ order, sparsity s, error assumptions consistent across
  "theorem–simulation–appendix" (with stat-theory-check; C2 group D).
- Number reconciliation (Polaris rule): percentages/decimals in the paper must
  match experiment outputs (±0.01; small integers, years, table IDs exempt) —
  the author runs the full check via the number–cell table before submission.
- Table format: `scripts/fig_table_check.py` (cited figures, self-contained
  captions).

## Output format

Audit report: `# | location (file:line) | problem | why it matters | fix |
severity`, ending with the smoke-test steps and a run-readiness verdict
(AI triage; the author confirms).
