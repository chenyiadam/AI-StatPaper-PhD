# stat-reviewer · 审稿模拟与修回

## 硬性纪律

1. **审稿意见是研究起点**：每条意见人工裁决（必须修 / 值得修 / 回信解释）；
   AI 审稿人也会误读论文——[疑似误读] 意见要回原文核实后再处理。
2. **离群意见降权**（AI Scientist/Polaris 聚合规则）：以中位数为锚，
   偏离中位数 > 3 分的意见标记离群；Confidence ≤ 2 的意见降权。
3. **分数买不回引用**（Polaris 通过规则）：`通过 = (overall ≥ 6) 且 (fabricated
   引用 = 0)`——只要有一条引用被核验为编造，模拟审稿直接不通过。
4. **对诚实说明局限不惩罚**：Limitations 是加分项（NeurIPS 惯例）。

## 工作流

### A. 三审稿人模拟（`prompts/06` P24）

三个**独立会话**分别执行（互不可见，temperature 建议 0.7 保持多样性）：

| 角色 | 关注面 |
|---|---|
| 统计理论审稿人 | 假设强弱、证明正确性、速率最优性、理论-方法一致 |
| 应用与计算审稿人 | 模拟公平性、基准调参、真实数据解读边界、复现包 |
| 表述与规范审稿人 | 结构逻辑、贡献-正文对应、图表自含、引用规范、AI 披露 |

Rubric（每个角色同构，便于聚合）：
- Soundness / Presentation / Contribution 各 1–4 分（附判据锚点）
- Overall 1–10（10=突破性，7=接受，5=borderline 慎用，3=拒绝）
- Confidence 1–5；**Decision 只允许 Accept / Reject 两个值**（禁止中间态，
  borderline 倾向写进理由）
- 意见必须指认位置（节/式/表号），无位置的意见删掉
- THOUGHT 直觉笔记 + REVIEW JSON 双输出（JSON 供程序聚合）

### B. Meta-review 聚合（P25）
1. 同类意见合并（标来源 R1+R3）；数值分以中位数为锚。
2. 每条 weakness 标注：`[可核实] / [需复核]（涉外部事实）/ [疑似误读]`。
3. 输出三档修改工作清单：必须修（soundness 或多人提及）→ 值得修 →
   回信解释；每条带预估工时与涉及章节。
4. 元评审结论：接收概率评估 + 最大风险点。
5. **保住核心主张**：三份意见全盘采纳 ≈ 改成分数最低审稿人想要的样子。

### C. 模拟闭环（建议跑两轮）
第一轮意见 → 修复 → 第二轮模拟验证修复效果 → 直到"必须修"清零。
发现理论实质漏洞则回滚 S3（stat-theory-check），这是正常流程。

### D. 真实修回（收到真实审稿意见后）
用 **P26** 起草逐条回复：先结论后论据、每条 ≤ 250 词、承诺对应真实修改、
数据/理论争议给可核验证据、误读意见先复述到对方满意再澄清。
输出 LaTeX 回复信（意见斜体、回复正体、修改处标蓝）。

### E. 投稿决策辅助
1. 期刊匹配度：论文贡献类型 vs 期刊近两年发文谱系（方法/应用/理论比例）。
2. 建议审稿人：从文献池挑 3–5 位无利益冲突的（方法脉络最近邻的作者优先，
   排除合作者）。
3. Cover letter 草稿：一句话贡献 + 适合该刊理由 + 无一稿多投声明。

## 输出格式

模拟审稿汇总表：
```
| 意见 | 来源 | 位置 | 类别(理论/实验/表述) | 裁决(必修/值得修/解释) | 状态 |
```
末尾：三档清单 + Overall 中位数 + 接收概率初判（AI 估计，仅供参考）。
