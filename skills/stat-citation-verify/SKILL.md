# stat-citation-verify · 三层引用核验

## 硬性纪律（本 skill 的存在理由）

1. **默认立场：AI 给出的每条引用，在人工核验通过前视为不存在。**
   通用大模型在开放文献问答中的引文幻觉率高达 78%–90%（OpenScholar, Nature）。
2. **无法验证 ≠ 无效**：API 故障、网络超时一律输出"未验证"，
   永不输出" fabricated"判定（Polaris 规则）——判定降级要大声，不许悄悄放行。
3. **转引不可接受**：L3 核验必须打开原文 PDF；只看摘要不算通过（摘要核验
   只能标"部分核验"）。
4. **绝不删除被标记的引用**：核验发现问题 → 报告给作者裁决（改引/删引/换引），
   AI 不自行处理。

## 三层核验流程（每条引用）

### L1 · 存在性（这条论文真的存在吗）
1. DOI 可解析：`https://doi.org/<DOI>` 指向该题名；或 Crossref API：
   `https://api.crossref.org/works/<DOI>`。
2. Google Scholar / Semantic Scholar 检索题名命中。
3. 作者真实：该作者确有此方向其他工作（AI 常缝合两位真实作者）。
4. 卷(期)、页码与出版商页面逐字一致；arXiv 号格式正确。
5. **红旗信号**：题名"太完美"贴合论点、期刊名与主题错位、
   中文文献查无刊期（AI 幻觉中文文献率高，知网二次确认）。

### L2 · 字段一致性（bib 条目对吗）
1. BibTeX 条目从出版商官方导出（Google Scholar 导出 + 出版商页面对照），
   **禁止直接采用 AI 生成的条目**。
2. 作者列表完整且顺序正确；年份区分在线先发/正式出版；期刊名全称缩写统一；
   arXiv 预印本已正式发表则替换。
3. 机械检查交给 `scripts/citation_check.py`：正文-bib 双向一致、必填字段、
   TODO 残留、journal+arXiv 并存告警。

### L3 · 内容支撑（原文支持你的论点吗）
1. 打开 PDF，直奔"该论点应有证据形式"的位置（定理？数值实验？讨论段？）。
2. 三种不支撑情形鉴别：
   - **条件缺失型**：原文结论有条件，引用弱化了条件（统计文献最常见）
   - **强度错位型**：原文数值实验结论被写成理论结论
   - **张冠李戴型**：结论相似但属于另一篇文献
3. 引用位置恰当性：方法起源/定理出处/数据来源各自引对——
   **定理出处错误是审稿人极反感项**。
4. 更优来源检查：同样结论有更早/更权威原始文献则改引。

## 输出格式（每条引用一张核验卡）

```
引用：作者 (年份) 题名. 期刊 卷(期):页. DOI
L1 存在性：通过/可疑（证据：doi.org 结果、Scholar 命中）
L2 字段：通过/修正（逐字段对照结论；修正后条目附上）
L3 支撑：支撑/部分支撑/需改写/无法判断（原文证据位置：节/页/段）
作者动作：可直接使用 / 需改写引用句 / 需换文献 / 需人工再核
核验记录：日期 · 动作清单 · PDF 存放路径
```

## 批量模式（全文核验）

1. `scripts/citation_check.py main.tex refs.bib` 出形式问题清单。
2. 逐条生成核验卡（L1/L2 可批处理，L3 必须逐条人工）。
3. 汇总表：总条数 / L1 通过率 / L2 修正数 / L3 状态分布 / 待人工项。
4. 收尾过 `checklists/C6-引用核验清单.md` 收尾组（密度、分布、记录留存）。
