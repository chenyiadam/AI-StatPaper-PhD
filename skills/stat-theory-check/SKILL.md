# stat-theory-check · 理论推导与证明审查

## 硬性纪律

1. **定理的核心想法由作者提出**：分解策略、关键不等式、假设取舍是人定的；
   AI 负责起草技术细节、检查一致性、攻击证明。
2. **AI 生成的证明默认有跳步与幻觉引用**：逐行审查（模式 B）是必经工序。
3. **"显然"是禁区**：证明中任何"显然/易得/clearly/it is easy to see"都要展开
   或替换为明确引理引用。
4. **AI 报告"证明成立"≠成立**：正确性由作者最终裁决；本 skill 的产出是
   "嫌疑点清单 + 修复建议"。

## 三种工作模式

### 模式 A · 定理体系设计（新理论）
1. `prompts/03-理论推导与检查.md` **P08**：主定理草案 → 引理清单（依赖 DAG、
   已知程度、风险）→ 速率定位 → "假设-证明位置"匹配自检。
2. 用 **P11** 逐条审假设（语义精确性/标准性/强弱定位/可验证性/使用位置）。
3. 输出定理依赖图（无环）+ 每条假设的 Remark 草稿。

### 模式 B · 证明逐行审查（最常用）
1. 作者给出证明稿 + **允许引用的引理清单**（清单外视为不可引用）。
2. 用 **P10** 以六类问题扫描：Q1 幻觉引用 / Q2 跳步 / Q3 收敛模式混用 /
   Q4 维数与常数 / Q5 事件完整性（好事件+坏事件两部分） / Q6 偷偷用陈述外条件。
3. **建议双模型交叉**：同一证明用两个不同模型各审一次，意见取并集，
   人工裁决每条（AI 也有误报：把正确步骤报成错误）。
4. 对照 `checklists/C2-理论检查清单.md` C 组（C1–C14）逐项人工确认。

### 模式 C · 反例构造（假设能否放松）
1. 用 **P12**：对候选弱化条件构造显式反例（DGP 定义 → 逐条验证满足假设 →
   证明结论失效 → 指出踩中哪个证明环节）。
2. 反例的"满足假设"验证步骤**逐步重算**——AI 反例常不满足它自己声称的条件。
3. 反例成立 → 写进假设的 Remark（"该条件不可去"，附录给出反例，这是加分项）；
   不成立 → 回模式 A 放松假设。

## 高频漏洞速查（AI 生成证明的重灾区）

| 漏洞 | 检查动作 |
|---|---|
| 引用不存在的引理（如 Lemma 3.2 从未出现） | 对照引理清单逐条核编号 |
| $O_p/o_p$ 运算非法（如 $o_p+o_p$ 写成 $o_p$ 的平方） | 逐条检查随机阶运算 |
| 依概率与 a.s. 混用 | 标注每个收敛结论的模式并核对 |
| 只证好事件、忘坏事件概率 | 搜 "on the event" 确认 $\mathcal{E}^c$ 处理在 |
| 极限与求和/积分/期望随意交换 | 找控制条件（DCT/MCT/一致收敛） |
| $p$ 依赖 $n$ 时当常数用 | 检查维数条件与矩阵秩论证 |
| 引用文献定理但条件更强 | 拉原文核对（引用核验联动） |
| λ 阶与目标函数罚项归一化不匹配 | 对照式 (1) 的 $1/n$ 因子 |

## 交叉检查（与其他 skill/脚本联动）

- 记号一致性：跑 `scripts/notation_check.py`（重复宏、悬空引用、
  未引用定理、"显然"扫描、TODO 残留）。
- 理论-模拟一致（λ 阶、稀疏度、DGP 假设体现）：stat-simulation-audit。
- 证明中引用的文献定理逐条过 stat-citation-verify 的 L3（原文是否真有
  该定理且条件满足）。

## 输出格式

审查报告（每个证明一份）：
```
结论判定：成立（小修）/ 有实质漏洞 / 路线不可行
问题清单：Q# | 位置(行/式) | 类别 | 具体理由 | 建议修法 | 严重度
假设-使用对照表：Assumption k → 使用于 Step j ✓/冗余/未用
待作者裁决项：AI 不确定的地方逐条列出
```
