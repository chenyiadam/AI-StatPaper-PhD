# 04 · 阶段三：理论推导与证明

> 配套：`prompts/03-理论推导与检查.md`（P08–P12）· `checklists/C2-理论检查清单.md`
> · `skills/stat-theory-check/SKILL.md`
> 本阶段目标：建立定理体系并完成经得起 Referee #2 攻击的证明。

## 本项目对 AI 理论能力的立场

1. **定理的想法由人出，技术细节由 AI 起草，攻击由 AI 执行，裁决由人做。**
   分解策略、关键不等式、假设取舍是论文的灵魂，交给 AI 就失去了作者资格。
2. **AI 生成的证明默认有跳步与幻觉引用。** P10 逐行审查是必经工序。
   真实案例级别的错误模式：引用不存在的引理编号、把 $O_p$ 运算写错、
   依概率与 a.s. 收敛混用、只证好事件不控坏事件概率。
3. **双模型交叉审查**：同一证明用两个不同模型独立攻击，意见取并集。
   单模型有系统性盲区（它自己写的跳步它自己看不出来——换模型能暴露）。

## 推荐工作流

```
P08 定理体系设计（主定理草案+引理DAG+假设-使用对照）
  → 作者手推证明骨架（路线、关键不等式、步骤）
  → P09 AI 起草证明细节（禁偏离路线；新需求显式标注）
  → P10 双模型逐行攻击（六类问题扫描）
  → C2 清单人工裁决
  → P11 假设强弱审查（语义/标准性/可验证性/使用位置）
  → P12 反例构造（试攻最弱假设；成则写进 Remark，败则放松假设）
  → notation_check.py（记号/编号/残留）
```

## C2 清单的高频考点（审稿人真实关注点）

- **C1 极限交换**：$\lim\sum \ne \sum\lim$；控制收敛定理的条件验证要写出来。
- **C6 事件完整性**：好事件上的界 + 坏事件概率控制，两部分都在——
  只证一半是 AI 证明最常见的结构性缺陷。
- **C7 KKT 条件**：次梯度符号、罚项归一化（$1/n$ 因子）与 λ 阶匹配。
- **C8 维数**：$p$ 依赖 $n$ 时不能当常数；矩阵秩、特征值界的维数依赖。
- **C14 引用核对**：证明里每个 "by [Ref, Thm 2]" 拉原文核对条件——
  AI 常引用编号错误或条件更强的定理。
- **D 组理论与方法对应**：定理针对的估计量 = 式 (1) 的目标函数；
  理论 λ 阶 = 模拟 λ 取值。AI 在长上下文中极易"串味"成另一个变体。

## 证明呈现的统计论文惯例

1. 正文：Assumptions（编号可讨论）→ Main theorem → Remark（速率最优性
   对比、λ 实践建议）→ Proof sketch 三句话。全文证明在附录。
2. 附录：先证 auxiliary lemmas（A.1, A.2, …），再按定理顺序给全文证明；
   每个被引用的中间结果必须先于使用出现。
3. 假设要有 Remark：与文献假设的强弱对比、能否放松、真实数据下是否合理。
4. "该条件不可去"的反例放附录是**加分项**（P12 的产出）。

## 速率最优性检查（顶刊审稿人的固定问题）

主定理给出速率后，回答三问：
1. 与 minimax 下界是否匹配（Le Cam / Fano / 两点法论证，核对散度计算）？
2. 若不匹配，缺口在哪一步（近似误差？正则化偏差？）——Remark 里诚实说明。
3. 文献中同问题的最优速率是多少（引文核对）？
