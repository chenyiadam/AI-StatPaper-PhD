# 07 · 阶段六：审稿模拟

> 配套：`prompts/06-审稿与投稿.md`（P24–P27）· `checklists/C7-投稿前终检清单.md`
> · `skills/stat-reviewer/SKILL.md`
> 本阶段目标：在真实审稿人之前，用 AI 审稿人把论文的漏洞暴露出来并修复。

## 机制设计（来自 AI Scientist / Polaris 的验证过的做法）

1. **三审稿人 + 角色隔离**：统计理论 / 应用计算 / 表述规范，三个独立会话，
   互不可见（防止意见趋同），temperature 0.7 保持多样性。
2. **结构化 rubric**：Soundness / Presentation / Contribution 各 1–4 分
   （带判据锚点）+ Overall 1–10 + Confidence 1–5 + **二值决策**
   （只许 Accept/Reject，borderline 倾向写进理由——便于统计与聚合）。
3. **意见要有位置**：每条 weakness 必须指认节/式/表号；无位置的意见作废。
4. **意见本身要过可靠性筛查**：`[可核实] / [需复核] / [疑似误读]` 三档标注；
   AI 审稿人也会幻觉（指控你没引用一篇不存在的文献）。
5. **聚合规则**：同类合并标来源；中位数为锚；偏离中位数 > 3 分的意见
   标离群人工复核；Confidence ≤ 2 降权。
6. **通过门槛**：`通过 = (Overall 中位数 ≥ 6) 且 (fabricated 引用 = 0)`。

## 两轮模拟闭环（建议流程）

```
第一轮 P24（三角色）→ P25 聚合 → 修复（必修项清零）
→ 第二轮 P24（验证修复；换模型或换会话）→ 残余意见裁决
→ P27 结构自检（只读）→ 决定投稿
```

发现理论实质漏洞 → 回滚 S3（正常流程，流水线为此设计）。

## 修回（收到真实审稿意见后）

P26 起草逐条回复。语气模板：

- 先结论后论据；每条 ≤ 250 词；开头致谢一句话即可。
- **已修改**：改了什么 + 位置（Section X, page Y, lines Z）+ 新文本引用
  （≤ 3 行）+ 为什么这能解决关切。
- **解释**：理解对方关切 → 统计层面的保留理由（理论约束/领域惯例/
  文献做法）→ 补敏感性分析或脚注降低歧义。
- **疑似误读**：先复述对方观点到对方满意（"If we understand correctly…"），
  再给澄清；绝不写"审稿人误解了"。
- 承诺必须对应真实修改——回信里每个"已修改"都要能指到 diff。

## 审稿人视角的"一票否决点"（修复优先级最高）

1. 基准方法没调参（稻草人对照）
2. size 失控（nominal 5% 实测 8%+）且无解释
3. 定理引用出处错误
4. 理论 λ 阶与实验取值不一致
5. 引用幻觉（一条就够）
6. 摘要数字与正文不一致
