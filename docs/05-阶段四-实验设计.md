# 05 · 阶段四：实验设计与复现

> 配套：`prompts/04-实验设计与审计.md`（P13–P16）· `checklists/C3-实验检查清单.md`
> · `templates/simulation/`（R/Python 骨架）· `skills/stat-simulation-audit/SKILL.md`
> 本阶段目标：模拟"演给定理看"，真实数据"落一地可复现"，
> 所有数字可溯源到输出文件。

## 全局原则：确定性代码做重活，LLM 只做判断

（Polaris 实验引擎的原则，本项目全盘采纳）
- 跑实验永远是脚本的事。AI 不"心算"数值结果；AI 解读只能引用表格里
  真实存在的数字。
- **数字对账规则**：论文正文的百分数/小数必须与实验输出匹配
  （±0.01 容差）；小整数、年份、表号豁免。这条规则写进 S5 的写作纪律
  和 S6 的审稿 rubric。

## 模拟研究四要素（缺一即重做）

1. **场景网格**：n × p × s × 信号 × 误差分布 × 方法。每个取值说明
   "对应定理哪条假设的满足/边界/违反"——模拟是定理的实验化陈述。
   必须含定理的边界场景（如 n 刚好越过 s log p 条件）。
2. **DGP 规范**：逐式对应论文公式（脚本注释写 DGP-1, DGP-2…）；
   重尾误差与正态同方差可比；**种子规则化** seed = base + 1000×场景 + 重复。
3. **指标一次算全**：估计误差（两种范数）、模型选择（TPR/FDR）、
   推断有效性（覆盖率对真参数、区间长度、size、power）、计算时间。
   改指标重跑 = 场景漂移，是自欺。
4. **基准公平性**：每个基准同网格调参（防"稻草人对照"——审稿人
   一票否决项）；用各基准的公认最优实现。

## 流程与工具

```
P13 设计五件套 → sim_design.R/.py 骨架填空 → P14 代码审计
→ 10分钟冒烟测试（n=50,p=10,rep=20）→ 全量运行（后台、分批、断点续跑）
→ P15 结果解读（数字-单元格对照表）→ P19 图表 → 复现包
```

冒烟测试是博士生的救命稻草：数量级不对、覆盖率算成对估计值、
重尾没标准化——10 分钟就能暴露，全量跑完才发现 = 一周白费。

## 结果解读的诚实条款

- 与理论预期**不一致**的场景必须如实写出并给候选解释——
  这是论文可信度的来源，不是弱点。
- 禁止跨场景平均掩盖异质性；禁止表里没有的数字；
  相对比较给百分比 + 绝对值。
- size 解读给区间（"0.052–0.061 across scenarios"）。

## 真实数据分析的特殊纪律

- 解读措辞分级：`与…相一致` < `表明` < `证明`——观测数据上
  "证明因果"需要识别假设成立且有编号。
- 预处理规则先于看数据定（离群值规则不许画完图再定）。
- 至少一个敏感性分析（缺失值两种处理对照 / 超参扰动）。
- 数据可得性声明必写；受限数据写获取流程。
