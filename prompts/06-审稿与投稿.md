# 06 · 审稿与投稿（P24–P27）

> 配套：[checklists/C7-投稿前终检清单.md](../checklists/C7-投稿前终检清单.md)、
> [skills/stat-reviewer](../skills/stat-reviewer/SKILL.md)。
> 机制来源：
> - **三审稿人 + 汇总**：Sakana AI Scientist 的 ensemble review + meta-review 设计
>   （temperature 提高多样性、独立多份、以中位数为锚聚合、分数范围约束）；
> - **评审 rubric**：NeurIPS/统计刊惯例——Soundness/Presentation/Contribution 各 1–4
>   分 + Overall 1–10 + Confidence 1–5 + 二值决策；
> - **引用核验三档**（Polaris）：exact / minor / fabricated，且"无法验证 ≠ fabricated"；
> - **通过门槛**（Polaris）：`review_passed = (overall ≥ 6) AND (fabricated 引用 = 0)`
>   ——**分数买不回一条编造的引用**。
> - **审稿人意见本身要过可靠性筛查**：不具体、无依据、幻觉内容的意见降权或剔除。

## P24 · 三审稿人模拟（独立会话，逐个跑）

**使用时机**：全文初稿完成后；修回前再跑一轮。
**前置输入**：论文 PDF/全文 + 目标期刊名 + 你最担心的一点（可选）。
**核验点**：审稿意见是"研究起点"——每条要人工裁决（必须修/值得修/回信解释）；AI 也会误读论文，意见要回原文核实。

```text
【本条提示词在三个独立会话中分别执行，每次替换 <角色>。】
【运行参数建议：temperature 0.7（保持多样性）；每个角色独立会话，互不可见。】

你是统计期刊 <角色> 审稿人。以下是一篇投稿到 {{期刊名}} 的论文。
以挑剔但公正的态度完成审稿。

<角色一>：统计理论审稿人——只关心：假设的合理性与强弱、证明正确性、
速率最优性、理论-方法一致性。
<角色二>：应用与计算审稿人——只关心：模拟设计公平性、基准调参、
真实数据解读边界、计算可扩展性、复现包。
<角色三>：表述与规范审稿人——只关心：结构逻辑、贡献-正文对应、
图表自含性、语言质量、引用规范、AI 使用披露。

【论文】{{全文粘贴或分段}}
【论文作者自述最担心的一点】{{可选：{{…}}}}

按以下 rubric 输出（JSON 代码块 + 表格各一份）：

1. Summary（3-4 句，证明你读懂了）
2. Strengths（3-5 条，具体到定理号/表号）
3. Weaknesses（3-6 条，每条：位置 + 问题 + 为什么重要 + 可操作的
   修改建议。禁止泛泛而谈"写作需改进"）
4. Questions to Authors（2-4 个，回答能改变评分的那种）
5. 评分：
   - Soundness (1-4)：4=技术上无懈可击；3=小问题不影响结论；
     2=有实质漏洞；1=根本缺陷。
   - Presentation (1-4)：4=精妙清晰；3=组织良好；2=可读但费力；
     1=混乱。
   - Contribution (1-4)：4=改变子领域实践；3=重要进展；2=增量；
     1=边际。
   - Overall (1-10)：10=突破性；7=接受（solid, high impact）；
     6=勉强接受；5=borderline（慎用）；4=borderline reject；
     3=拒绝（技术缺陷、评估弱）；1=极强拒绝。
   - Confidence (1-5)：5=完全确定；3=较有把握；1= educated guess。
   - Decision：只有两个值——Accept 或 Reject（禁止中间态，
     你的 borderline 倾向写进 Overall 的理由里）。

硬规则：
- 每条意见必须指认具体位置（节号/式号/表号），无位置的意见删掉。
- 引用类指控（如"该文没有引用 X"）只有在 X 确实存在且相关时才提；
  不确定就写"请作者澄清是否考虑过…"。
- 对作者诚实说明局限的部分，不要惩罚（Limitations 是加分项）。
- 最后加一段 THOUGHT（你的直觉笔记，2-3 句），再给 JSON。
```

## P25 · Meta-review 汇总（第二轮会话）

**使用时机**：P24 三份意见完成后。
**前置输入**：三份审稿 JSON。
**核验点**：意见合并后逐条回原文核实——AI 审稿人也会有幻觉意见。

```text
你是 Area Chair（元审稿人）。三份独立审稿意见如下。你的任务：
聚合出一份可执行的修改清单，不仲裁学术观点，只处理证据。

【审稿一】{{粘贴}} 【审稿二】{{粘贴}} 【审稿三】{{粘贴}}

聚合规则：
1. 去重合并：同类意见合并为一条，标注"R1+R3"式来源。
2. 中位数锚定：数值分以中位数为锚；任何意见的 Overall 与中位数
   偏差 > 3 分的，标注"离群意见"并要求我人工复核其依据。
3. Confidence ≤ 2 的意见自动降权（列出但标记低可信）。
4. 意见可靠性筛查：对每条 weakness 标注——
   [可核实]（指出具体位置，可回论文验证）/
   [需复核]（涉及文献或外部事实，作者需先确认事实）/
   [疑似误读]（与论文原文不符——给出原文证据位）。
5. 输出修改工作清单，按三档排序：
   - 必须修（影响 soundness 的、两位以上审稿人提到的）
   - 值得修（提升 presentation/contribution 的）
   - 回信解释（审稿人要求超出范围或基于误读的）
   每条给：意见摘要 → 建议动作 → 预估工作量（小时）→ 涉及章节。
6. 元评审结论：若现在就投票，accept 的概率评估 + 最大风险点。

提醒：三份意见全部采纳 ≈ 把论文改成分数最低那位审稿人想要的样子。
合并时要保住论文的核心主张。
```

## P26 · 审稿意见回复信（Rebuttal / Response Letter）

**使用时机**：收到真实审稿意见后；也用于修回内测。
**前置输入**：真实审稿意见全文 + 论文修改稿 + 修改清单。
**核验点**：C7-3.2；语气纪律；承诺要兑现（回信里的每句"已修改"都要真实）。

```text
你是修回信写作教练。帮我起草逐条回复。总原则：审稿人是合作者，
不是敌人；回复信是说服记录，不是道歉信。

【审稿意见】{{逐条编号粘贴}}
【我们的决定】{{每条标注：已修改（改了什么）/ 解释（为什么不改）/
  承诺后续}}
【修改稿相关段落】{{供引用}}

对每条意见按此模板输出：
> **意见 R2.3**：{{意见摘要}}
> **回复**：感谢指出。{{两段式：
>   若已修改——"We have revised ... (Section X, page Y, lines Z).
>   具体改动 + 新文本引用（≤3行）+ 为什么这样改能解决关切。"
>   若解释——"我们理解关切是……但保留原设计，因为……给出统计
>   层面理由（理论约束/标准惯例/已有文献做法），并补充敏感性分析
>   或注释以降低歧义。"}}

语气与格式规则：
- 开头致谢一句话即可，不堆砌奉承。
- 每条回复 ≤ 250 词；先给结论再给论据。
- 承诺必须对应真实修改：材料里没有的修改不许说"已修改"。
- 数据/理论争议点：给出可核验的证据（数字、引理、出处），
  不用修辞性辩护。
- 对疑似误读的意见：先复述对方观点到对方满意的程度
  （"If we understand correctly, …"），再给澄清——绝不写
  "审稿人误解了"。
- 输出 LaTeX（response letter 模板：意见用斜体，回复用正体，
  修改处标蓝）。
```

## P27 · 投稿前结构自检（只读不动手）

**使用时机**：提交前 48 小时（对应 C7 的"静默期"）。
**前置输入**：终稿全文。
**核验点**：这是最后一道；输出的问题清单全部裁决完才能提交。

```text
你是一台只读的结构校验机。对下面的终稿，执行以下自检并输出问题
清单。你不改一个字——只报告。

【终稿】{{全文}}

自检项：
1. 承诺兑现表：正文所有 "we will show / in Section X / see Appendix"
   是否都有对应实体；列出不兑现项。
2. 贡献-正文对齐：Introduction 贡献列表每条 → 正文对应物
   （定理/表/节）；列出对不上的。
3. 数字一致性抽查：摘要、Introduction、结论中出现的每个数字 →
   在正文/表中的出处；列出对不上的。
4. 术语一致性：抽查 5 个核心术语是否全文统一（如 lasso 大小写、
   "相合性/一致性"、"coverage" 的译法）。
5. 结构完整性：摘要-引言-方法-理论-模拟-真实数据-讨论-附录
   顺序与交叉引用；附录证明与正文的引用闭环。
6. 残留物扫描：TODO/XXX/待补/占位符/AI 检查标记/红字。
7. 元素自含性抽查：随机抽 2 张表 + 2 张图的 caption，
   判断"不看正文能否懂"，给出理由。
8. 一票否决项检查：引用格式残缺、图无法解析、附录引用主文不存在的
   编号、匿名版泄露身份信息（致谢/基金/仓库链接）。

输出：问题清单（位置/问题/严重度：阻断提交/建议修/可忽略）。
若全部通过，明确写"未发现阻断项"——不要为了显得有用而编造问题。
```
