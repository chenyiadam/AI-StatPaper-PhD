## P33 · 研究章程（S0：立项规划）

**使用时机**：S1 之前或并行；合作项目必须在动笔前完成。
**前置输入**：问题陈述草案 + 数据/算力现状 + 合作者名单。
**核验点**：AI 的角色是"审问你的计划"，不是替你规划；数据可得性、算力、
授权必须由人确认。

```text
你是课题组的项目管理顾问。审问以下研究计划，找出会让论文延期或
流产的缺口。你只提问与列清单，不替我做决定。

【计划草案】{{问题一句话 + 预计周期 + 数据来源 + 算力条件 + 合作者}}
【目标产出】{{目标期刊梯队 + 预印本意向}}

逐项审问并输出：
1. 里程碑倒排：从"目标投稿月"倒推——理论完成/实验完成/初稿/审稿模拟/
   期刊适配/投稿，各留多少周？总缓冲 ≥ 25% 吗？哪一段最容易超期
   （通常是理论卡壳或数据申请）？
2. 数据可得性预检：数据申请流程多长？有没有伦理审批？若申请失败，
   备选数据集是什么（现在写进章程，不是失败后再找）？
3. 算力预算：模拟网格的预估核时（对照 P13 的网格）从哪来？
4. 作者分工协议（CRediT taxonomy 逐人确认）：
   Conceptualization / Methodology / Software / Validation / Formal analysis /
   Investigation / Data curation / Writing – original draft / Writing – review
   & editing / Visualization / Supervision / Funding acquisition。
   作者顺序今天书面确认，投稿前不再谈。
5. 预注册决策树（回答三问）：
   - 目标期刊是否接受/欢迎 Registered Reports 格式？
   - 真实数据分析是否需要在看到结局前固定预分析计划（PAP）？
     若是：主分析/敏感性分析/排除规则逐条预登记（OSF）。
   - 都不是 → 明确写"不预注册，理由是方法论研究、无确证性检验"，
     留档备审稿人问。
6. 文献监控计划：arXiv 订阅关键词、Google Scholar Alerts、
   每月一次"有没有人抢发"扫描（谁负责、多久一次）。
7. 风险登记册：每项风险 → 触发信号 → 预案（B 方案）→ 责任人。
```

## P34 · 投稿系统执行清单（S8）

**使用时机**：投稿日当天。AI 生成"该刊字段填写方案"，你逐字段执行。
**前置输入**：目标期刊投稿系统（Editorial Manager / ScholarOne / 自建）+
作者指南投稿页 + 全部文件清单。
**核验点**：技术性拒稿（格式）占初期拒稿相当比例——本清单就是防它。

```text
你是投稿系统操作顾问。基于该期刊的作者指南，生成一份逐字段填写方案。

【投稿系统】{{系统名 + 截图或字段清单}}
【文件清单】main / anonymized main / supplement / replication package /
cover letter / reporting checklist（如适用）
【元数据】标题/摘要/关键词/作者与单位/基金/致谢

输出：
1. 文件预检：每个文件——命名符合系统要求？格式正确（PDF/Word/TeX 源）？
   匿名版泄漏扫描已做（致谢/基金/自引/仓库链接/文件属性作者名）？
   图表分辨率与格式符合要求？文件大小限制内？
2. 强制字段映射（逐字段给出填什么）：
   - Data availability statement（对照复现包 DOI）
   - Funding statement（基金号全称与格式）
   - Conflict of interest（全体作者逐人）
   - AI use disclosure（一句概括 + 指向附录 D）
   - Ethics/IRB、临床试验注册号（如适用）
   - CRediT 作者贡献（对照 P33 章程）
3. 常见技术性一票否决点自查：字数/页数、摘要字数、关键词数量、
   参考文献样式、图表数量上限、补充材料大小。
4. 提交序列：先传什么后传什么（顺序错了系统可能用错版本）；
   提交后下载 receipt PDF 逐页目检；记录投稿编号与投稿日期（催稿要用）。
5. 提交后 48 小时内：确认系统状态变为 "with editor"/"under review"，
   未流转则发一次状态确认邮件（用 P36 模板 1）。
```

## P35 · 预印本策略（arXiv / SSRN 等）

**使用时机**：投稿前决定；每轮修改后执行同步。
**核验点**：期刊预印本政策逐刊核对（多数统计刊允许，个别有 embargo）。

```text
你是学术出版策略顾问。给出我的预印本决策与执行清单。

【论文】{{标题/领域/目标期刊}}
【作者情况】{{是否首次投 arXiv（决定 endorsement 问题）}}

输出：
1. 政策核对：目标期刊的预印本政策（允许/embargo/版本要求）——
   给出核对动作清单（查官网 + 与近期该刊论文的 arXiv 记录交叉验证）。
2. endorsement 门槛：首次投 arXiv 需要该分类下的 endorsement——
   列出获取路径（找谁：合作者/同方向有发过 arXiv 的学者；
   提前几周办；备选分类方案）。
3. 版本纪律：投稿版与 arXiv 版的关系——
   - 投稿前挂 arXiv：论文脚注引用 arXiv 号（供审稿人取复现包）
   - 每轮修回后：arXiv 同步更新版本号，changelog 写清改动
   - 录用后：arXiv 更新为 accepted version 并链接 DOI。
4. 许可证联动：arXiv license 选择与期刊 OA 政策的兼容性
   （默认选 arXiv 的非排他许可，除非期刊另有要求）。
5. 不挂预印本的理由清单（如双盲刊的顾虑、与合作者的约定）——
   决策写进 P33 章程，避免投稿周临时纠结。
```

## P36 · 状态询问与催稿（礼仪 + 三情形模板）

**使用时机**：超过期刊自述周期后。**原则：礼貌、低频、有据。**
**核验点**：催稿不加速审稿，只加速"遗忘的稿件"；每月超过一封询问信
会起反作用。

```text
你是学术出版礼节顾问。先给我决策规则，再按情形给模板。

【情形】{{填写：投稿编号 / 投稿日期 / 当前系统状态 / 期刊自述的平均周期}}

决策规则（先回答）：
1. 时机：desk decision 通常 2–6 周；外审 3–6 个月（以期刊官网自述为准）。
   超过自述周期 + 4 周才询问；同一稿件两次询问间隔 ≥ 6 周。
2. 对象： managing editor / 编辑部邮箱，永远不发给审稿人。
3. 内容：只陈述事实（编号、日期、超期时长），不暗示编辑失职。

三情形模板（英文信，各 ≤ 120 词）：
- 模板 1·周期超期询问：subject "Status inquiry — Manuscript ID {{}}";
  正文 = 一句话身份 + 一句话事实（投稿 X 月，系统状态 Y）+
  一句话请求（若有时间线信息烦请告知）+ 感谢。
- 模板 2·审稿停滞：若知道"Required reviews completed"状态已停 Z 周——
  请求指定一名替补审稿人或推进决策，语气仍是"供您参考"。
- 模板 3·修回稿长期无音讯：修回提交 X 个月无状态变化——
  询问是否需要作者补充任何材料。
每封信末尾自查：有指责语气吗？有超过事实范围的推测吗？有就删。
```

## P37 · 决策响应三路（录用 / 修改 / 拒稿）

**使用时机**：收到 decision 邮件当天。先冷静 24 小时再行动（拒稿尤甚）。

```text
你是出版流程顾问。按决策类型给我执行路径。

【决策】{{Accept / Minor / Major / Reject(-with-resubmit) / Desk reject}}
【意见】{{粘贴或概述}}
【约束】{{修改截止日 / 其他在投稿件 / 时间预算}}

A. 录用（Accept）→ 校样阶段走 P38。
B. 修改（Minor/Major）→
   1. 逐条意见进 P25 聚合 → P26 回复信 → 修改稿（走 S5/S6 纪律，
      不因"只是小修"跳过 style_check 与数字对账）。
   2. 时间线：收到意见 1 周内回信确认接受修改；若确需延期，
      模板（≤100 词）："正在完成补充实验，能否宽限至 X 月 X 日"
      ——延期申请一次到位（要 30–60 天），不要反复。
   3. 文献保鲜：修改前重跑一次检索（P33 的监控计划），
      近一年新文献该引的引，不该引的不硬引。
C. 拒稿（含 Desk reject）→
   1. 24 小时冷静期后做"意见分诊"：技术性错误（必须修）/
      范围不匹配（换刊即可）/ 误读（在 cover letter 里预防）。
   2. 申诉评估：仅当能证明事实性误判（如审稿人声称缺失的定理实际存在）
      才考虑申诉；申诉成功率低，默认路径是修改后转投。
   3. 转投决策：用 journals/ 档案重新选刊（吸收全部意见后再投；
      同一版本原样投姊妹刊 = 自毁口碑）；预印本同步更新。
   4. 心态条款：顶刊拒稿是流程的一部分；把审稿意见当成免费的
      stat-reviewer 集群。
```

## P38 · 校样与发表后（proofs → promotion → errata）

**使用时机**：录用后到发表后一个月。

```text
你是出版后期顾问。按阶段给我执行清单与模板。

【阶段】{{Proofs / 已上线 / 发表后发现错误}}

A. 校样（Proofs）纪律：
   1. 只改错排（typo/格式/图质量），不改内容——任何内容改动都要
      走 errata 程序，代价远大于保留瑕疵。
   2. Author Query 逐条回应格式：AQ1: author response…（简短精确，
      不重写句子）。
   3. 核对项：作者名拼写与顺序、单位、基金号、通讯标注、摘要与
      关键词、图表编号与清晰度、参考文献页码、ORCID。
   4. 返回时限：通常 48–72 小时，错过会拖累上线时间。
B. 版权与 OA 决策：license 选择（CC BY vs 署名-非商业）、
   OA 费用与绿色归档政策（自存档到机构库/arXiv 的版本约束）、
   页码/彩图费用（如适用）。
C. 发表后 30 天：
   1. 宣传清单（克制版）：课题组主页/机构新闻稿一句式介绍；
      社交媒体只陈述已证明的结论 + 复现包链接；不向同事群发 PDF
      （发 DOI 链接）。
   2. 监控：Google Scholar 引用提醒；发现实质错误 → 立即联系编辑
      走 errata/correction（模板：错误陈述 + 正确陈述 + 影响评估 +
      修复后的复现包更新）。
   3. 把审稿过程中沉淀的新清单条目回馈本项目（CONTRIBUTING）。
```
