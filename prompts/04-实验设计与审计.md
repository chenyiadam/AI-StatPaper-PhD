## P13 · 模拟实验设计（场景网格 + 指标定义）

**使用时机**：理论完成后、写模拟代码前。
**前置输入**：定理的假设与结论（模拟要"演给定理看"）；候选基准方法清单。
**核验点**：C3-A 组全项；特别是 A4（基准公平）与 A7（λ 与理论一致）。

```text
你是统计模拟实验设计专家。基于我的定理与候选基准，设计一套
"审稿人挑不出毛病"的模拟研究方案。

【定理陈述】{{粘贴：含假设、速率、λ 的阶}}
【方法】{{一句话：什么估计量/检验}}
【候选基准】{{列出：如 OLS、Lasso、Lasso+debiased、贝叶斯方法}}
【计算预算】{{核心数、预计总时长上限}}

输出四部分：

1. 场景网格表：
   维度：n | p | s（活跃集）| 信号强度 | 误差分布 | 相关结构
   每个维度给取值集合，并说明：
   - 每个取值为什么在网格里（对应定理哪条假设的"满足/边界/违反"）
   - 必须包含的"定理边界场景"（如 n 刚好越过 s log p 条件）
   - 网格总组合数 × 重复次数 × 方法数 = 总运行数，按我的预算裁剪，
     给出裁剪后网格与预计时长。

2. DGP 规范：写出数据生成伪代码（可转录为 R/Python），包括：
   - β0 的构造方式与信号强度定义式
   - 误差分布标准化方式（重尾要与正态同方差可比）
   - 每个场景的种子规则（seed = base + 1000*场景编号 + 重复序号）

3. 指标定义表：指标 | 公式 | 为什么选它 | 对应定理哪个结论。
   必含：估计误差（两种范数）、模型选择（TPR/FDR）、推断有效性
   （覆盖率、区间长度、size、power）、计算时间。
   明确标注：覆盖率是对真参数；预测误差用独立测试集。

4. 基准公平性协议：
   - 每个基准的超参怎么调（同网格 CV / 同 λ 序列），禁止"只给我调优"
   - 基准的已知最优实现库（R 包/Python 包名）
   - "稻草人对照"自查：如果审稿人问"你的 Lasso 基准调参了吗？"，
     每个基准都要能给出肯定回答。

5. 失败协议：方法不收敛/发散时记录失败率进表格，不静默丢场景。
```

## P14 · 实验代码审计（跑之前）

**使用时机**：模拟/分析代码写完、正式开跑前。**审代码比审论文便宜得多。**
**前置输入**：完整代码 + P13 的设计文档 + DGP 公式。
**核验点**：审计是初筛，确定性测试（单场景小 n 手算对照）仍是必须的。

```text
你是统计计算审计员。审计以下实验代码在"正式开跑"前的正确性。
你只找问题，不夸代码。

【设计文档】{{P13 输出}}
【代码】{{粘贴全部}}

逐项审计并输出编号清单（位置/问题/为什么是问题/修法）：

1. DGP 一致性：代码的数据生成与设计文档公式逐式对照（含标准化、
   信号定义、相关结构）——这是模拟实验第一大错误源。
2. 种子纪律：随机数种子的规则是否与文档一致；是否有隐藏的全局随机
   调用（如某些采样函数内部用默认 RNG）；并行时种子是否安全。
3. 统计正确性：
   - 覆盖率算的是不是真参数落入区间（不是估计值）
   - TPR/FDR 的分母与方向；空选中集合的处理
   - 自由度、标准化、检验统计量构造的公式正确性
   - λ/超参的取值是否与理论阶一致；CV 折数是否泄露未来信息
4. 边界与失败：收敛失败的捕获与记录（不静默 NaN）；空活跃集；
   n < p 场景下的退化行为。
5. 可复现性：输出文件带种子与日期；环境依赖可锁定；
   随机性全部经由受控 RNG。
6. 性能陷阱：明显可向量化处、内存峰值、并行粒度（按场景并行，
   不要按重复并行共享 RNG）。

最后：给我一份"10 分钟冒烟测试"清单——用最小参数（n=50,p=10,
rep=20）验证每个环节输出形态与数量级的具体步骤。
```

## P15 · 结果解读（表到文字的忠实转换）

**使用时机**：模拟跑完、写 5.2 节前。
**前置输入**：汇总结果 CSV/表 + 场景设计文档。
**核验点**：C3-C3——解读的每个数字与表格一致（跑 `scripts/fig_table_check.py`）；
禁止解读超出数据支持范围的"因果"表述。

```text
你是统计论文写作教练。把模拟结果表转换成论文 5.2 节"Results"的
文字初稿。你只能使用表里出现的数字，一个都不能多。

【结果表】{{粘贴或描述：行=场景×方法，列=指标，均值(标准差)}}
【场景设计】{{P13 的网格说明}}
【理论预期】{{定理预测：随 n 增大误差按 O(sqrt(s log p/n)) 降；
  误差重尾时方法 X 应更稳……}}

写作规则：
1. 结构：先总后分——第一段给跨场景的总体模式（哪类方法在哪类场景
   占优），后 2-3 段逐一讨论模式，最后一段点出与理论预期的对应。
2. 每个模式必须带具体数字支撑（"在 n=200, p=1000 场景下，
   方法 A 的 RMSE 为 0.123，较 Lasso 低 18%"），数字照抄表格。
3. 与理论对表：结果方向与定理预期一致吗？不一致的场景**必须如实
   写出**并给出候选解释（这是诚实，不是弱点）。
4. 语言纪律：不说"clearly/sig improvement"；相对比较给出百分比与
   绝对值；size 解读要给区间（"0.052–0.061 across scenarios"）。
5. 禁止：表里没有的数字、跨场景平均掩盖异质性、"趋势明显"这类
   无数字断言。
6. 输出后自查：列出你用过的全部数字及其出处单元格（给我一个
   "数字-单元格"对照表，我据此逐个核对）。
```

## P16 · 真实数据分析设计与写作

**使用时机**：模拟完成后，选取与预处理真实数据前。
**前置输入**：数据集元信息（来源、样本量、变量）；领域文献中该数据的既有分析。
**核验点**：C3-D 全项；特别是 D4（解读不超范围）与 D1（数据可得性）。

```text
你是应用统计与数据伦理双背景的顾问。帮我规划真实数据分析部分。

【数据集】{{来源/样本量/变量数/许可协议}}
【我的方法】{{一句话}}
【领域既有分析】{{该数据上已发表的结论方向（我所知）}}

输出：
1. 数据集适配性判断：
   - 该数据能回答什么、不能回答什么（对应我的方法的假设是否合理）
   - 样本量与维数是否进入我的定理适用范围；不在的话如何处理
     （如实说明"理论条件在此数据上无法验证，结果按探索性解读"）
2. 预处理协议（逐条可复现）：
   - 缺失值：方法选择理由 + 敏感性分析方案（至少两种处理对照）
   - 离群值：规则先于看数据（不许先画图再定规则）
   - 变量编码/标准化：写死在脚本里
3. 分析方案：
   - 主分析 + 至少一个敏感性/扰动分析
   - 与领域文献结论的对表计划（哪张表、哪些量可比）
4. 解读边界声明草稿：
   - 本数据是观测/实验？识别假设是什么？结论措辞上限在哪
     （"与…相一致" vs "表明" vs "证明"——给出对应措辞等级）
5. 写作模板：数据来源段（含可得性声明）、表 1（汇总统计）规格、
   结果段结构（先描述性再推断）、局限段（数据层面的具体局限）。

伦理检查：该数据的采集许可是否覆盖本用途；是否含需脱敏的标识信息；
引用数据集出处与许可证的规范格式。
```
